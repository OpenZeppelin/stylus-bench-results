= ERC-721 Consecutive

Consecutive extension for xref:erc721.adoc[ERC-721] is useful for efficiently minting multiple tokens in a single transaction. This can significantly reduce gas costs and improve performance when creating a large number of tokens at once. `_mint_consecutive` omits per-token `Transfer` events and receiver callbacks. The helper does not check whether it is running during construction, so the contract must only call it from its constructor. For a proxy, use it only during initial proxy deployment.

[[usage]]
== Usage

Compose `Erc721Consecutive` as a storage field. In SDK 0.10, use `#[implements]` to declare the interfaces the contract exposes. The constructor below only calls `_mint_consecutive`; do not add a public or otherwise reachable method that calls it later.

[source,rust]
----
use alloc::vec::Vec;
use alloy_primitives::{aliases::U96, Address};
use openzeppelin_stylus::{
    token::erc721::{
        extensions::{consecutive, Erc721Consecutive}, IErc721,
    },
    utils::introspection::erc165::IErc165,
};
use stylus_sdk::prelude::*;

#[entrypoint]
#[storage]
struct Erc721ConsecutiveExample {
    erc721: Erc721Consecutive,
}

#[public]
#[implements(IErc721<Error = consecutive::Error>, IErc165)]
impl Erc721ConsecutiveExample {
    #[constructor]
    fn constructor(
        &mut self,
        receivers: Vec<Address>,
        amounts: Vec<U96>,
        first_consecutive_id: U96,
        max_batch_size: U96,
    ) -> Result<(), consecutive::Error> {
        self.erc721.first_consecutive_id.set(first_consecutive_id);
        self.erc721.max_batch_size.set(max_batch_size);
        for (&receiver, &amount) in receivers.iter().zip(amounts.iter()) {
            self.erc721._mint_consecutive(receiver, amount)?;
        }
        Ok(())
    }
}

----

See the [complete ERC-721 Consecutive example source](https://github.com/OpenZeppelin/rust-contracts-stylus/blob/v0.4.0/examples/erc721-consecutive/src/lib.rs) for the token methods and burnable extension implementation.
