= Upgrading from 0.3.0

This guide covers the source and storage changes needed to move a Stylus contract
from OpenZeppelin Contracts for Stylus 0.3.0 to the SDK 0.10.10 based API.
Keep the old implementation available while deploying and validating an upgrade.

== Toolchain and dependencies

Use stable Rust 1.91.0 and pin the SDK and command line tools to 0.10.10:

[source,toml]
----
[dependencies]
stylus-sdk = "=0.10.10"
alloy-primitives = "=1.5.7"
alloy-sol-types = "=1.5.7"

[dev-dependencies]
stylus-tools = { version = "=0.10.10", features = ["integration-tests"] }
----

The migration updates Alloy from 0.7 to 1.7 and its exposed primitive and
Solidity ABI types from 0.8 to 1.5. Since contract APIs expose `Address`,
`U256`, and Alloy-generated types, update any direct Alloy dependencies and
`sol!` imports together. The workspace also requires `ruint` 1.17.1 or newer.

The workspace now uses Cargo-aware `stylus-tools` projects. Each deployable
example has its own `Stylus.toml`; add one to a consumer contract and use it for
local activation and deployment. SDK 0.10.9 added pinned Binaryen optimization
recipes, but the SDK 0.10.10 devnet's Nitro parser rejects the `DataCountSection`
emitted by Binaryen 116. The examples therefore leave `[wasm-opt]` unset and
deploy the Rust compiler's Wasm output. Verify a pinned optimizer against the
exact Nitro version used for deployment before adding it to a project.

== VM accessors

Host values and logs now come from the contract's VM. Replace global accessors
with the corresponding method on `self.vm()`:

[cols="1,1"]
|===
|Old |New

|`msg::sender()` |`self.vm().msg_sender()`
|`msg::value()` |`self.vm().msg_value()`
|`contract::address()` |`self.vm().contract_address()`
|`contract::balance()` |`self.vm().balance(self.vm().contract_address())`
|`block::timestamp()` |`self.vm().block_timestamp()`
|`block::number()` |`self.vm().block_number()`
|`block::chainid()` |`self.vm().chain_id()`
|`block::basefee()` |`self.vm().block_basefee()`
|`block::coinbase()` |`self.vm().block_coinbase()`
|`block::gaslimit()` |`self.vm().block_gas_limit()`
|`tx::origin()` |`self.vm().tx_origin()`
|`tx::gasprice()` |`self.vm().tx_gas_price()`
|`evm::log(event)` |`self.vm().log(event)`
|`Address::has_code()` |`self.vm().code_size(address) > 0`
|===

This makes the host dependency explicit and allows the same contract logic to
run against the SDK `TestVM`.

Traits that read VM state now require a host-aware contract context. `IEip712`
inherits `HostAccess`; its `chain_id` and `contract_address` methods are
instance methods, so replace `MyContract::chain_id()` and
`MyContract::contract_address()` with `contract.chain_id()` and
`contract.contract_address()`. `IProxy` now also requires
`HostAccess<Host = VM>`, so update downstream unsafe implementations and pass
the context to the ERC-1967 helpers that previously used static methods.
`get_implementation`, `get_admin`, `get_beacon`, and `change_admin` take a
context; `upgrade_to_and_call` and `upgrade_beacon_to_and_call` require their
context type to implement `HostAccess<Host = VM>`.

== Typed contract calls

SDK 0.10 passes the VM host and call context separately to generated interface
methods. For a view call, pass `self.vm()` and `Call::new()`; for a state
changing call, pass `self.vm()` and `Call::new_mutating(self)`:

[source,rust]
----
let balance = erc20
    .balance_of(self.vm(), Call::new(), account)?;

erc20.transfer_from(
    self.vm(),
    Call::new_mutating(self),
    owner,
    recipient,
    amount,
)?;
----

`Call` is available from `stylus_sdk::prelude::*`. Prefer generated typed
interfaces for known contracts. Low level calls remain available for raw ABI
use cases. The SDK flushes storage caches around high level external calls;
this maintains coherent storage state across calls and does not replace
application level authorization or reentrancy protections.

== ERC-1967 utilities and custom storage slots

`Erc1967Utils::get_implementation`, `get_admin`, and `get_beacon` now take a
contract context so they can access the VM. Pass `self` from contract code:

[source,rust]
----
let implementation = Erc1967Utils::get_implementation(self);
let admin = Erc1967Utils::get_admin(self);
let beacon = Erc1967Utils::get_beacon(self);
----

`StorageSlot::get_slot` also takes an explicit VM. Pass a clone of the VM
handle returned by `self.vm()`:

[source,rust]
----
let implementation = StorageSlot::get_slot::<StorageAddress>(
    IMPLEMENTATION_SLOT,
    (*self.vm()).clone(),
);
----

The `BeaconProxy` keeps its old ordinary storage field reserved so the proxy's
storage layout does not move. Its public `get_beacon()` now reads the canonical
ERC-1967 beacon slot. Existing proxies initialized by the old constructor have
that slot populated and keep their ABI and upgrade behavior.

== Public interface traits

SDK 0.10 requires every interface trait in a `#[public]` implementation,
including inherited traits, to carry `#[public]`. Add the attribute to those
traits before compiling. The SDK also checks for selector collisions in public
implementations. Resolve collisions before deployment while preserving the
selectors expected by existing clients; use an explicit selector rename only
when the ABI change is intended. If an interface trait uses
`#[selector(name = "...")]`, apply the same selector to its public
implementation; `#[interface_id]` computes the advertised ERC-165 id from the
trait but does not currently verify that a separate public implementation uses
the same selector (the open v0.2 audit item M-02).

The SDK's ABI decoder rejects malformed encodings that older versions could
accept. Return canonical ABI data from external contracts and update mocks that
returned truncated or otherwise noncanonical values.

== Unit and integration tests

The library's unit tests now use `stylus_sdk::testing::TestVM` and its explicit
storage, host, call, and log controls. Replace legacy fixture macros with
`TestVM` fixtures. Mock calls to external contracts with the matching calldata
and return data; TestVM does not execute a second Rust fixture as if it were an
on-chain contract.

The old `lib/e2e` and `lib/e2e-proc` harnesses have been removed. Integration
tests use the SDK's `stylus-tools` devnet runner. Run the repository E2E script
to build, activate, and exercise the scenarios against the local devnet:

[source,sh]
----
./scripts/e2e-tests.sh
----

The SDK runner starts a Nitro devnet through Docker/Testcontainers and may need
to download its container image. Keep Docker running and allow image access.
The repository test support deploys compiled test contracts with
`cargo stylus deploy --no-verify` because these artifacts are exercised only on
the local devnet. For a real deployment, use the SDK's default reproducible
build and verification path; do not copy this test-only flag into a release
script.
When porting a consumer's own E2E tests, preserve both success and revert cases
and deploy all participating contracts to the same devnet. The test projects
declare `contract-client-gen = []` so the SDK's generated-client feature cfg is
recognized by Cargo; keep this feature declaration in copied templates.

Use the repository scripts to check Wasm size and compare gas measurements:

[source,sh]
----
./scripts/check-wasm.sh
./scripts/bench.sh
----

Install `cargo-stylus` 0.10.10 for reproducible builds and local devnet
activation. SDK 0.10.9 includes an optional optimizer version and flags in the
project hash and uses the same recipe for deployment and verification; the
examples omit that recipe because its Binaryen 116 output is rejected by the
Nitro version bundled with SDK 0.10.10's devnet. SDK 0.10.10 reports paused
Stylus activations as a distinct error; wait for activations to resume before
running deployment or devnet activation checks.

SDK 0.10.5 deprecated the `reentrant` feature because high-level SDK calls
flush the storage cache around external calls. In SDK 0.10.10, the generated
entrypoint still rejects reentrant calls unless this feature is enabled. Most
contracts should remove the old feature because they do not need callbacks
into themselves. A flash lender or another contract that deliberately supports
callbacks must keep it enabled until the SDK removes the guard:

[source,toml]
----
[dependencies]
openzeppelin-stylus = { version = "=0.3.0", features = ["reentrant"] }
----

The library preserves this compatibility feature and forwards it to the SDK.
Storage cache flushing preserves state coherence; it is not a reentrancy guard
or a replacement for checks-effects-interactions ordering and callback
authorization.

== Storage layout changes

ERC-721 enumerable keeps its v0.3.0 storage layout. Owner-index bounds now come
from the composed contract's core ERC-721 balance, so token ID zero is
distinguishable from an unset mapping entry without adding storage or requiring
a proxy data migration. The Solidity ABI of `IErc721Enumerable` is unchanged.
When forwarding its Rust method, pass the core component explicitly:

[source,rust]
----
fn token_of_owner_by_index(
    &self,
    owner: Address,
    index: U256,
) -> Result<U256, Error> {
    self.enumerable
        .token_of_owner_by_index(&self.erc721, owner, index)
}
----

If a contract relied on `Erc721Enumerable` implementing the public interface
directly, move that forwarding implementation to the containing contract so it
can supply the matching `Erc721` component. Existing proxy deployments need no
enumeration storage migration.

`BeaconProxy` keeps its ordinary beacon field in place as reserved storage, so
that field does not shift subsequent proxy storage. ERC-1967 implementation,
admin, and beacon values remain in their standard hashed slots.

The ERC-721 consecutive extension now rejects `_mint_consecutive` after
deployment with `ERC721ForbiddenBatchMint`, as required for constructor-only
consecutive minting. The SDK installs code before invoking the constructor, so
the extension also recognizes the SDK's canonical `StylusDeployer` caller as
the construction context. Move batch mint calls into the constructor. This
changes the error behavior for contracts that previously exposed this internal
helper after deployment; it does not change the ABI of standard ERC-721
functions.

== ABI and behavior

Standard token and proxy selectors and event layouts remain unchanged. The
SDK's selector collision checks may reject an application that previously
compiled; resolve the collision without changing selectors that deployed
clients rely on.

The following observable behavior changes are intentional:

* ERC-2981 uses a 10,000 denominator when fresh storage contains zero and uses
  full-precision `sale_price * numerator / denominator` arithmetic. Queries
  that previously divided by zero or overflowed now return a floored royalty.
* Vesting schedules use full-precision multiplication and division, so large
  representable allocations that previously overflowed now vest normally.
* The ERC-721 wrapper rejects an underlying address with no code using
  `ERC721UnsupportedToken` before deposits or withdrawals. Configure the
  wrapper with a deployed ERC-721 contract.
* ERC-20 wrapper and ERC-4626 deposits assume exact-transfer underlying tokens.
  Fee-on-transfer and deflationary assets can leave shares underbacked and are
  unsupported; choose an exact-transfer token before deploying a wrapper or
  vault. This follows the same asset compatibility requirement as the
  Solidity ERC-4626 implementation.
* ERC-4626 construction now rejects decimal offsets when `10^offset` exceeds
  `U256` or when asset decimals plus the offset exceeds `U8`, returning
  `ERC4626InvalidDecimalsOffset`. Offsets above 77 are always invalid. This
  also changes the Rust `Erc4626::constructor` helper to return `Result`; the
  constructor's external ABI remains unchanged. The guard applies when a
  constructor runs; it does not rewrite or validate the stored offset of an
  existing proxy. Check existing vault storage before an upgrade, and add a
  project-specific migration if it contains an invalid offset.
* Safe ERC-20 helpers accept no return data or a canonical `true` bool in the
  first return word. A malformed word such as `2`, which older decoding could
  treat as `true`, now returns `SafeErc20FailedOperation`. The bounded host
  read still ignores any return bytes after that first word. Tokens returning
  canonical `true` or no data keep their success behavior; `false` remains a
  failed operation.
* The SafeERC20 example now takes an explicit initial owner and gates every
  helper with `Ownable`. It appends the owner component after the existing
  SafeERC20 storage. Existing proxy instances of this example do not gain an
  initialized owner; redeploy them or initialize equivalent authorization in a
  migration before enabling token-moving methods.
* When `Erc20Wrapper::_recover` cannot query the underlying token, the
  `ERC20InvalidUnderlying` error now identifies the configured underlying
  address in its argument. The error selector is unchanged.
* EdDSA verification rejects identity or otherwise invalid public keys. Review
  any consumer that accepted those keys under the old behavior.
* `_mint_consecutive` after deployment now returns
  `ERC721ForbiddenBatchMint`, as described above.
* ERC-4626 conversions continue to follow the standard rounding direction and
  can return zero shares for a small deposit. `previewDeposit` is only a
  quotation; applications that require a minimum output must check a
  caller-supplied share bound atomically with the deposit.

The enumerable length tracking is internal storage and does not change ERC-721
ABI. Test wrapper and proxy integrations against the deployed implementation
before upgrading, especially if application contracts override public methods
or rely on malformed external ABI responses.
